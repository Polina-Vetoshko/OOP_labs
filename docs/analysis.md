Задание 1.2. 

1. 

Выделяются три класса:

`Game` — управляет игровым циклом и правилами.
Отвечает за: генерацию секретного числа, хранение лимита попыток, проверку догадки, завершение игры.
Обоснование: все данные и действия, связанные с правилами игры, логически группируются в одну сущность. Если бы `Game` ещё и печатал в консоль или читал ввод — это уже две ответственности, поэтому вывод вынесен в `UI`.

`Player` — представляет игрока.
Отвечает за: имя, счётчик сделанных попыток, получение ввода от пользователя (через `UI`).
Обоснование: счётчик попыток — это состояние игрока, а не игры. Если игроков станет двое, `Game` не должен меняться, достаточно создать два объекта `Player`.

`UI` — абстракция над вводом/выводом.
Отвечает за: `show_message()` и `get_input()`.
Обоснование: единственная причина, по которой этот класс может меняться — смена способа взаимодействия. Это классический принцип единственной ответственности.

Такое разделение устраняет главные проблемы процедурного кода: глобальные переменные, смешение логики и ввода-вывода, невозможность подменить ввод в тестах.


2. 

Приватными делаются все атрибуты, которые описывают внутреннее состояние объекта и не должны изменяться извне напрямую:

| Класс | Атрибут | Модификатор | Почему |
|---|---|---|---|
| `Game` | `_secret` | `_` | Значение не должно меняться после генерации. Снаружи доступ — только через `@property secret` (только для чтения, для тестов). |
| `Game` | `_max_attempts` | `_` | Задаётся один раз в конструкторе, менять его во время партии нельзя. |
| `Game` | `_ui` | `_` | Зависимость, инжектируется через конструктор. Снаружи знание о ней не нужно. |
| `Player` | `_name` | `_` | Имя задаётся при создании, читается через `@property name`. |
| `Player` | `_ui` | `_` | Та же причина, что и у `Game._ui`. |


3. 

Публичными делаются только те методы, которые образуют интерфейс класса — то, что действительно должны вызывать снаружи:

| Класс | Публичный метод | Зачем публичный |
|---|---|---|
| `Game` | `run()` | Точка входа — с неё начинается игра. Её вызывает `main.py`. |
| `Game` | `check_guess(guess) -> str` | Публична, потому что возвращает результат проверки и легко тестируется без запуска всего цикла. |
| `Player` | `make_guess() -> int` | Единственный способ получить от игрока корректное число. |
| `Player` | `increment_attempts()` | Единственный способ увеличить счётчик, инкапсулирует логику изменения. |
| `UI` | `show_message(message)` | Публичный интерфейс вывода. |
| `UI` | `get_input(prompt)` | Публичный интерфейс ввода. |


**Принцип:** если метод не нужен ни одному внешнему объекту — он не должен быть публичным. Это уменьшает связанность и оставляет свободу менять внутреннюю реализацию без риска сломать чужой код.
